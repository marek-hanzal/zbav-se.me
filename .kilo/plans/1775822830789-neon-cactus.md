# Agent Chat UI – Live Stream Architecture Plan (v3)

## Summary

`useAgent.ts` already pushes raw `AgentEvent[]` into the query cache via `withAgentLiveQuery.useSet()`.
The goal of this plan is to build the UI layer that subscribes to that event stream, where each sub-component is responsible for deriving its own state from the slice of events it cares about.

**No complex remapping in `useAgent.ts`** – it stays a dumb event accumulator.

---

## Architecture

### Data Flow

```
Server (SSE)
  └─ useAgent.ts (mutationFn)
        └─ liveQuery((prev) => [...prev, event])   ← appends raw AgentEvent to cache
              ↓
        withAgentLiveQuery cache: AgentEvent[]
              ↓ (via useQuery { select })
        LiveList.tsx       ← subscribes, derives output_index list
          ├─ ThinkingIndicator   ← select: events with type "response.reasoning_*"
          ├─ AssistantMessage    ← select: events where output_index === props.outputIndex
          │     └─ ToolCallBlock ← select: events for tool call within that output
          └─ ErrorMessage        ← select: events of type "response.failed" | "response.error"
```

### Component Tree

```
AgentPage
  └─ Agent.tsx
        └─ AgentMessageList.tsx
              ├─ HistoryList.tsx       ← AgentInputItem[] from withAgentStreamItemsQuery
              │   ├─ UserMessage.tsx
              │   ├─ AssistantMessage.tsx (history, static)
              │   └─ SystemMessage.tsx
              └─ LiveList.tsx          ← AgentEvent[] from withAgentLiveQuery
                  ├─ ThinkingIndicator.tsx
                  ├─ AssistantMessage.tsx (live, event-driven) × N
                  │   └─ ToolCallBlock.tsx × N
                  └─ ErrorMessage.tsx
```

---

## Core Subscription Pattern

`withAgentLiveQuery` already exists as `withQuery<void, AgentEvent[]>`.

TanStack Query's `select` option (passable via `opts` in `withQuery.useQuery`) enables granular subscriptions. Each component calls:

```typescript
withAgentLiveQuery.useQuery(undefined, {
  select: (events) => /* derived state specific to this component */,
});
```

TanStack Query only re-renders the component when the **selected value** changes (structural equality), so a `ThinkingIndicator` won't re-render on a text delta event.

**`useSet()` in `useAgent.ts` stays exactly as-is** – calling `liveQuery((prev) => [...prev, event])` is the only mutation point.

## Event-to-Component Mapping

| Event type | Component that handles it |
|---|---|
| `response.queued` | LiveList (clears previous run's events on new run start) |
| `response.reasoning_text_delta` | ThinkingIndicator (show) |
| `response.reasoning_text_done` | ThinkingIndicator (hide) |
| `response.output_item.created` | LiveList (spawns new AssistantMessage with output_index) |
| `response.text_delta` | AssistantMessage (append content) |
| `response.text_done` | AssistantMessage (finalize) |
| `response.tool_call.created` | AssistantMessage → spawns ToolCallBlock with call_id |
| `response.tool_call.done` | ToolCallBlock (show input+output, remove spinner) |
| `response.output_item.done` | AssistantMessage (mark complete) |
| `response.completed` | LiveList (trigger history invalidation) |
| `response.failed` / `response.error` | ErrorMessage |

## Implementation Detail per Component

### `LiveList.tsx`

Responsibilities:
- Subscribe to `withAgentLiveQuery` to derive the list of **output indices** present in the stream (events of type `response.output_item.created` each carry an `output_index`)
- On `response.queued`: reset – call `liveQuery(() => [])` to clear the accumulated events from a previous run
- On `response.completed`: invalidate `withAgentStreamItemsQuery` so HistoryList auto-refreshes
- Render `ThinkingIndicator`, one `AssistantMessage` per known `output_index`, and `ErrorMessage`

```typescript
// Select: derive ordered list of output_index values
const outputIndices = withAgentLiveQuery.useQuery(undefined, {
  select: (events) => {
    const seen = new Set<number>();
    const result: number[] = [];
    for (const event of (events ?? [])) {
      if (event.type === "response.output_item.created" && !seen.has(event.output_index)) {
        seen.add(event.output_index);
        result.push(event.output_index);
      }
    }
    return result;
  },
});
```

Side-effects (clear on queued, invalidate on completed) are handled via `useEffect` watching a derived boolean from the same query.

### `ThinkingIndicator.tsx`

```typescript
const isThinking = withAgentLiveQuery.useQuery(undefined, {
  select: (events) => {
    const last = (events ?? []).findLast(
      (e) => e.type === "response.reasoning_text_delta" || e.type === "response.reasoning_text_done"
    );
    return last?.type === "response.reasoning_text_delta";
  },
});
// Render: SpinnerContainer + translator.text("Agent is thinking") when isThinking
```

### `AssistantMessage.tsx` (live)

Props: `{ outputIndex: number }`

```typescript
// Select: all events for this output_index
const state = withAgentLiveQuery.useQuery(undefined, {
  select: (events) => {
    const mine = (events ?? []).filter(
      (e) => "output_index" in e && e.output_index === props.outputIndex
    );
    // Derive: content text (reduce text_delta), tool call IDs (tool_call.created)
    return deriveLiveMessageState(mine);
  },
});
```

`deriveLiveMessageState` is a pure function that reduces events into:
```typescript
interface LiveMessageState {
  content: string;
  toolCallIds: string[];   // IDs of tool calls (from tool_call.created events)
  isComplete: boolean;     // true after output_item.done
}
```

Renders: accumulated text content + one `ToolCallBlock` per `toolCallId`.

### `ToolCallBlock.tsx`

Props: `{ callId: string }`

```typescript
const state = withAgentLiveQuery.useQuery(undefined, {
  select: (events) => {
    const created = events?.find(e => e.type === "response.tool_call.created" && e.item.id === props.callId);
    const done = events?.find(e => e.type === "response.tool_call.done" && e.item.id === props.callId);
    return {
      name: created?.item.name ?? "",
      isComplete: !!done,
      input: done?.item.arguments ?? null,
      output: done?.item.output ?? null,
    };
  },
});
// Render:
// - isComplete: false → SpinnerContainer + tool name
// - isComplete: true  → Tool Call: <name> / Input: { json } / Output: { json }
```

### `ErrorMessage.tsx`

```typescript
const error = withAgentLiveQuery.useQuery(undefined, {
  select: (events) => {
    const errorEvent = (events ?? []).findLast(
      (e) => e.type === "response.failed" || e.type === "response.error"
    );
    return errorEvent ?? null;
  },
});
```

### `HistoryList.tsx`

Props: `{ items: AgentInputItem[] }`

- Uses `ts-pattern` to match `item.role` → `UserMessage | AssistantMessage | SystemMessage`
- Static; auto-refreshes via query invalidation from `LiveList` on `response.completed`

## `useAgent.ts` Changes

Two additions:

1. **Reset event log** at the start of `mutationFn`, before the stream begins:
   ```typescript
   liveQuery(() => []);  // clear stale events from previous run
   ```
   History is already persisted server-side, so dropping the live event log is safe.

2. **Invalidate history** on stream completion in `onSuccess`:
   ```typescript
   onSuccess() {
     withAgentStreamItemsQuery.invalidate(queryClient);
   }
   ```
   `queryClient` is obtained via `useQueryClient()` at the top of the hook (same as `liveQuery`).

---

## `withAgentLiveQuery.ts` Changes

**None.** It is already `withQuery<void, AgentEvent[]>` with `queryFn: () => []`. This is correct — it acts as an in-memory event log, not a server-fetched resource.

## Key Conventions

- All live components follow **namespace props pattern**: `export namespace AssistantMessage { export interface Props ... }`
- `data-ui` contract: `LiveList`, `LiveList-ThinkingIndicator`, `LiveList-AssistantMessage`, `LiveList-ToolCallBlock`, `LiveList-ErrorMessage`
- One component per file
- No inline complex types in function signatures – local named aliases only
- `ts-pattern` for role dispatch in `HistoryList`
- `translator.text(...)` for all visible strings
