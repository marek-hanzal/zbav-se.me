# AGENTS.md

## Sources and scope

- This file defines shared implementation policy. Read the nearest relevant `README.md` before changing an area; keep detailed procedures there.
- `MASTER.md` describes product intent in Czech. Follow its status and open decision IDs; unresolved draft rules require a product decision before implementation.
- Write code and technical documentation in English. Keep `MASTER.md` in Czech and preserve the established language of product copy. Explicit user language instructions take precedence.
- Inspect Git status before editing. Preserve concurrent work and keep changes within the requested scope. Propose a separate Linear issue for substantial unrelated work; a direct user request does not require an existing issue.

## Repository and tools

- Application code lives in `src/`; shared utilities and primitives live in `lib/{client,common,server}/`. Maintenance CLIs, Vitest tests, Playwright tests, and static assets live in `cli/`, `test/`, `e2e/`, and `public/`.
- Import aliases come from `tsconfig.json`: `~/` maps to `src/`, `@/lib/` to `lib/`, and `~/test/` to `test/`.
- Tool versions live in `mise.toml`; commands live in `Argcfile.sh`. Run commands from the repo root through `argc` (or `mise exec -- argc` without shell activation).
- Use npm with `package-lock.json` and `tsx` for TypeScript CLIs. Keep project commands out of `package.json`; it holds package metadata and dependencies.
- Do not start or restart the development app or proxy unless the user requests it. Coordinate checks that share build outputs, test ports, or running servers.
- `src/_route.ts` is generated by TanStack Router. Change route sources and let the normal build regenerate it.

## Domains and server boundaries

- Keep code in its owning domain. `.dependency-cruiser.cjs` defines enforced import boundaries on resolved paths; do not weaken it to make a change pass.
- Buyer and seller must not import each other; common must not depend on either; public must not import user. Keep `lib/common` independent of client/server code and keep `lib/client` and `lib/server` separate.
- Keep server internals out of client code. Use the approved function/schema surfaces and existing middleware/composition patterns; inject Effect services at the composition edge.
- Enforce authorization, ownership, sensitivity, bans, lifecycle, limits, and rate limits on the server. UI visibility is not enforcement; never bypass a gate to make a flow work.
- Preserve Kysely and Zod contracts and inferred function types. Validate external input at the boundary; do not replace shared contracts with duplicate local shapes or unchecked assertions.
- Keep cross-domain exports close to their owning implementation and respect import boundaries. Do not introduce the retired `~public/` re-export wrappers.

## Routes and UI

- Routes live in `src/@routes`; screen and page component trees live in the owning domain's local `ui/` folders. Query wrappers belong in `query/`, mutation wrappers in `mutation/`.
- Each UI page route delegates rendering to its own domain `*Page`. Root/layout routes, redirects, and server/API/XML endpoints do not need artificial page components.
- Route files contain route configuration, search validation, guards/loaders, metadata, and thin render adapters. Keep business logic and page UI in the owning domain.
- Read `Route.useParams`, `Route.useSearch`, `Route.useLoaderData`, etc. in route adapters and inject the mapped values through props. `*Page` components must not import or call Route APIs.

## Code and components

- Exactly one React component per file.
- Prefer namespace props: `export namespace ComponentName { export interface Props ... }` with `export const ComponentName: FC<ComponentName.Props>`.
- Extend base UI props when applicable (`Container.Props`, `Button.Props`, ...), keep wrappers pass-through (`...props`), and merge `ui` defaults with `...ui` last. Prefer grouped `hooks` props for multiple callbacks.
- No ad-hoc type holder files (`foo-props.ts`, `types.ts`, `type.ts`). Infer types from existing contracts or define named aliases beside the implementation; no inline complex types in signatures or variables.
- Namespace lettercase must match the symbol (`foo -> namespace foo`, `Bar -> namespace Bar`).
- Prefer local constants and direct logic over helpers for straightforward operations. Put necessary helpers after the main exported code.
- Apply these conventions to new and changed code. Keep cleanup related to the task; existing violations do not justify weakening the rules.

## `data-ui` contract

- Root: `Component[Element]`
- Child: `Component-[Element]`
- State: `Component[Element.state]` or `Component-[Element.state]`
- Dynamic variant: ``Component-[Button.${value}]``
- `Component` and `Element` use PascalCase; `state` uses lowercase. Labels must be semantic and stable.
- Normalize touched legacy free-form labels to this bracket format.

## Verification and handoff

- Update the relevant `README.md` when changing documented behavior, contracts, structure, or workflows; avoid unrelated documentation churn.
- Use `argc format`. Always run `argc workflow:check` before handoff: it normalizes the manifest, formats, typechecks, lints, checks dependencies, and builds. It writes fixes and stops at the first failure; review the resulting diff.
- `workflow:check` does not run tests. Run relevant Vitest tests with `argc test <path>` and Playwright scenarios with `argc e2e --grep <pattern>` when behavior requires them. Pass arguments directly, without an extra `--`. Documentation-only changes do not need new tests.
- Test setup may build Docker infrastructure. Inspect the test configs before overlapping suites or rerunning servers in a shared checkout.
- Report what was checked and any failures or skipped checks. Keep unrelated failures explicit; do not disable checks or expand the task just to get green output.
- Before committing, inspect the staged paths and diff and include only the authorized changes. Commit and PR text is English; push only when requested.
